THE ONE ERROR, AND WHY IT IS NOT THIS WORLD'S
---------------------------------------------
WASM_003 is the capability cross-check. It does NOT read the levels table: it
reads a hardcoded map, HOST_FUNCTION_CAPABILITIES in
packages/core/src/constants.ts, built from Content Spec v1.0 section 5, and that
map stops at the 72 level-1 functions (k_ui_show_world_text / k_ui_hide_world_text
/ k_ui_show_notification are there at constants.ts:682-684; k_ui_prompt is not
anywhere in the file). An unmapped kosmos.* name is rejected as unverifiable.

`--host-surface` cannot reach it. The flag selects the levels table, which drives
WASM_007 (and the required-level arithmetic); it is not consulted by WASM_003.
So on origin/main e66ccfd NO level-2 world can validate, whatever surface is
passed — this world is simply the first one to prove it.

The fix is one row in the publisher, in the NEW-06b/level-2 lane, not here:

    k_ui_prompt: "ui_basic",     // beside k_ui_show_notification

plus the two capability-free level-2 names (k_api_version, k_has_fn) in
FUNCTIONS_NO_CAPABILITY when they are called by anything. NEW-10 owns
`guestbook/**` in KosmosWorlds and does not touch the publisher.

RUN 2 below applies exactly that one row to the LOCAL SCRATCH WORKTREE's built
`dist/constants.js` — never committed, never pushed, never in this PR — to show
that WASM_003 is the only thing between this world and a clean bundle. The
reviewer of PR #1 reproduced both runs independently, in their own worktree,
and got the same two results.
