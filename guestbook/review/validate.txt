HISTORY — the finding this world filed, and how it was closed elsewhere
===============================================================================

This world was built against publisher origin/main e66ccfd. There, the escape
hatch did NOT work: WASM_003 rejected k_ui_prompt whatever surface was passed,
because it read a hardcoded map (HOST_FUNCTION_CAPABILITIES, constants.ts) that
the --host-surface flag never reached, and that map stopped at the 72 level-1
functions. No level-2 world could validate at all; this one was the first to
prove it. It was reported from this package as a finding for the publisher lane.

That was fixed by kosmos-worldpublisher PR #86 (fb9b801, merged after e66ccfd),
which made WASM_003 resolve through `resolveImportCapability` — canon first,
the levels table second for anything canon does not list. Hence RUN A: the flag
now reaches the check, and the same bytes that once needed a hand-patched
validator now pass an unmodified released one.

Two other fixes landed in the same window and both touch this package:

  9348261  the bundled manifest reports a real wasm size. The NEW-10 reviewer
           flagged `wasm_size_kb: 0` for a 3,878-byte module as a publisher
           arithmetic bug worth a ticket. The rebundled artifact here reads
           `wasm_size_kb: 5.4`, so that observation is closed, by someone else.

  8c8e18b  WASM_004 checks export SIGNATURES, not only names. This world exports
           k_init () and k_shutdown () with no result and k_tick (param f32),
           which the reviewer had verified by hand against the client's actual
           call shapes. RUN A passing under the stricter rule is independent
           confirmation of that reading.

Earlier revisions of this file carried the e66ccfd runs, including one made
against a locally patched dist/constants.js. That patch is gone and is no longer
needed by anything: every run above is an unmodified published build.
